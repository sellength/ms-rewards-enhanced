💡 微软官方弹窗认证机制与会话说明

1. 微软官方窗口原生认证： 点击“登录”后，系统将在本地弹出真实的微软官方浏览器窗口，请直接在官方窗口中完成账号与密码认证。

2. 全面支持全部官方双重验证： 无论你的账号使用微软 Authenticator 手机弹窗、短信验证码、邮箱验证码还是 Windows Hello / Passkey 免密验证，均可在官方弹窗中正常交互完成。

3. 免明文密码与本地会话存储： 本程序无需输入且绝不收集您的微软账号密码。官方弹窗登录成功后，程序将提取会话 Cookie 保存在本机 sessions/sessions.db（权限受限为仅当前系统用户可读写），用于后台自动执行积分任务。会话 Cookie 属于高权限登录凭据，请妥善保护本机数据目录。

4. 随时一键退出彻底清理： 点击“退出登录”后，保存在本地数据库中的会话 Cookie、账号元数据与缓存均会被彻底删除，完全恢复到未登录状态。

🛡️ Web 控制台安全与设备配对

1. 记住此浏览器（长期免密访问）： 首次通过带外配对码验证后，当前浏览器已获得独立长期凭据（通过 HttpOnly; SameSite=Strict Cookie 存储）。日常关闭/重新打开浏览器、Docker 容器重启或更新重建均可无感直接访问，无需重复输入配对密码。

2. 严格区分控制台授权与微软账号：

  • 微软账号退出登录（上方按键）： 仅删除保存在本机的微软账号 Cookie 与积分缓存，不影响控制台设备授权；
  • 退出控制台 / 撤销授权（下方按键）： 撤销当前浏览器对 Web 控制台的访问许可，下次访问必须重新输入配对密码。

3. 重新配对与保护边界： 本机制并非不可撤销的“字面永久”。设备凭据拥有 90 天有效期且活跃访问时自动滑动续期。当您在浏览器中主动清理 Cookie、更换新浏览器或点击“撤销授权”时需重新配对。注意：修改 MS_WEB_PAIRING_SECRET 仅影响后续新设备首次配对；已有设备基于服务端 auth_epoch 校验，若需让所有已授权浏览器立即重新配对，请管理员点击下方“⚡ 撤销所有设备授权”。
